# *Travel RAG — Туристический гид*

## *Блок 10. Вариант 117 Разработка нейросетевого ассистента*

Локальное веб-приложение для планирования знакомства с городом, подбора
достопримечательностей и получения справочной информации. Ответы строятся
по туристическим статьям Wikivoyage и документам, загруженным пользователем.

## <a id="vvedenie"></a> 1. Введение

### 1.1. Цель работы

Освоить принципы Retrieval-Augmented Generation и разработать
нейросетевого ассистента в виде веб-сайта с семантическим поиском по базе
знаний и пользовательским документам.

В RAG-приложении перед генерацией ответа выполняется поиск подходящих
материалов. Найденные фрагменты становятся контекстом для языковой модели.

### 1.2. Предметная область

#### Вариант 117 — «Туристический гид».

База знаний содержит сведения о достопримечательностях, музеях, городских
районах, транспорте и путешествиях. Пользователь может дополнить её собственным или справочным документом.

| Функионал              | Назначение | Пример задачи |
|------------------------|---|---|
| Планирование маршрутов | Подбор остановок и распределение по дням | Первое знакомство со Стамбулом за два дня |
| Рекомендации           | Подбор мест с учётом интересов и ограничений | Художественные музеи или парки без музеев |
| Справочная информация  | Ответ на конкретный вопрос по источникам | Высота башни, история здания, особенности |

### 1.3. Задачи разработки

1. Подготовка: очистить статьи, сохранить метаданные,
   разделить тексты на перекрывающиеся фрагменты.
2. Создать эмбеддинги и сохранить их в векторной базе данных.
3. Реализовать загрузку и обработку PDF, DOCX и TXT.
4. Организовать семантический поиск с учётом города и контекста диалога.
5. Интегрировать локальную LLM для подготовки поисковых запросов и генерации
   кратких ответов.
6. Разработать веб-интерфейс с регистрацией.
7. Выполнить проверки и сравнить генерацию с RAG
   и без поиска по источникам.

### 1.4. Соответствие требованиям задания

|---|---|---|

### 2.4. Роль LLM и программных проверок

| Этап | Что выполняется |
|---|---|
| Подготовка поиска | LLM переформулирует вопрос для поиска по англоязычному корпусу, сохраняя интересы и ограничения |
| Поиск | E5 вычисляет эмбеддинг; ChromaDB возвращает близкие фрагменты |
| Уточнение контекста | Код сопоставляет названия с исходными записями и проверяет принадлежность описаний |
| Генерация | LLM кратко пересказывает выбранные факты по-русски |
| Контроль результата | Код проверяет числа, типы объектов, повторы, количество пунктов и ссылки |
| Подготовка маршрута | Код выбирает остановки, распределяет по дням и формирует структуру карточек |

Для типовых свойств используются короткие формулировки, полученные из проверенных полей источника.
Для остальных описаний применяется ограниченный пересказ с дополнительными проверками чтоб модель не врала.

Из-за использования слабой модели перевод невсегда точен,
но сохраняет понятное краткое описание с сохранением смысла и фактов.

### 2.5. База знаний и её подготовка

Источник датастеа —
[yuiseki/wikivoyage-geotagged](https://huggingface.co/datasets/yuiseki/wikivoyage-geotagged),
англоязычный набор. В локальной конфигурации указан снимок от 1 сентября 2026 года. 
При использовании материалов сохраняются сведения об источнике и ссылки на статьи.

Показатели подготовленного датасета:

| Показатель | Значение |
|---|---:|
| Прочитано исходных записей | 29 505 |
| Сохранено статей | 29 486 |
| Сохранено чанков | 226 479 |
| Пропущено слишком коротких текстов | 19 |
| Размер чанка корпуса | До 220 слов |
| Перекрытие соседних чанков | 40 слов |
| Минимальная длина статьи | 120 символов |
| В среднем чанков на статью | 7,68 |

При подготовке проверяются обязательные поля, уникальность идентификатора,
ссылка на статью, длина текста и корректность координат. 
Текст нормализуется:
обрабатываются HTML-сущности, Unicode и лишние пробелы.

- У статьи сохраняются article_id, title, url, qid, координаты источник. 
- У чанка дополнительно сохраняются chunk_id, положение в статье, число чанков и количество слов.
- Координаты в наборе относятся к географическим объектам исходных статей.

### 2.6. Векторное представление и хранение

Размер эмбеддинга — 384 компоненты. Входные тексты модели ограничены
512 токенами, поэтому размер чанков в словах не равен гарантированному
количеству токенов. Длинный вход может быть усечён энкодером.

При векторизации используются префиксы passage: для документов и query:
для вопросов, а также нормализация векторов. 

| Хранилище | Содержимое |
|---|---|
| data/chroma, коллекция wikivoyage_e5_small_v1 | 226 479 эмбеддингов, тексты и метаданные |
| data/chroma, коллекция travel_user_docs_e5_small_v1 | Чанки загруженных документов с идентификаторами диалога и файла |
| data/processed/articles.jsonl | Полные исходные статьи |
| data/web_history.sqlite3 | Пользователи, сессии, диалоги, сообщения, метаданные документов |
| data/cache/article_offsets.sqlite3 | Вспомогательный индекс смещений статей в JSONL |
| data/cache/route_descriptions/ | Кэш описаний остановок |

Меньшее расстояние означает более близкие векторы; оно не является вероятностью правильности
ответа. SQLite хранит историю и служебные данные, векторный поиск выполняет
ChromaDB.

### 2.7. Контекст и особенности трёх режимов

#### Справочная информация.
Вопрос преобразуется в поисковую формулировку,
выполняется поиск по городу и его подстатьям. Найденные чанки дополняются
исходными записями о запрошенном объекте. Для ответа выбираются относящиеся
к вопросу факты со ссылками. Дата проекта отделяется от даты строительства.

#### Рекомендации.
Учитываются тип места, интересы, количество и исключения.
Из записей извлекаются кандидаты, затем дополнительно ранжируются E5.
Название района, улица или транспортный номер не должны становиться названием
музея. Описание соседнего объекта не считается подтверждением его коллекции.
При нехватке проверенных мест выдаётся меньший список.

#### Планирование маршрутов. 
Из статей города и районов выбираются подтверждённые
остановки. Алгоритм учитывает раздел путеводителя, тип объекта и упоминания
в обзоре достопримечательностей. Остановки группируются по дням, обычно
до трёх на день.

## <a id="razrabotka"></a> 3. Разработка, установка и развёртывание

### 3.1. Установка Python-зависимостей

Установка Python-зависимостей
Команды выполняются из корня проекта в терминале.

```
python -m pip install -r requirements.txt
```

### 3.2. Подготовка Ollama

Установите Ollama по
[официальной инструкции](https://docs.ollama.com/quickstart), затем загрузите
локальную модель [qwen3:1.7b](https://ollama.com/library/qwen3:1.7b):

```
ollama pull qwen3:1.7b
```

### 3.3. Настройки текущего сеанса

```
$env:OLLAMA_URL = 'http://127.0.0.1:11434'
$env:OLLAMA_MODEL = 'qwen3:1.7b'
```
Эти же значения используются по умолчанию. 

### 3.4. Подготовка векторной базы

Для установки с нуля:

```
python prepare_dataset.py --limit 0 --output data/processed
```

### 3.5. Далее создайте эмбеддинги всех чанков:

```
python build_vector_db.py --limit 0
```

### 3.6. Запуск веб-приложения

```
python web_app.py
```

### 3.7. Обработка пользовательских документов

## <a id="zakluchenie"></a> 5. Заключение

Разработан локальный туристический веб-ассистент с Wikivoyage
и возможностью загрузки пользовательских документов. Реализованы подготовка
текстов, чанкинг, векторизация, семантический поиск, интеграция LLM,
ссылки на источники, история, авторизация и журналирование.
Поддерживаются планирование маршрутов, рекомендации и справочная информация.

## <a id="prilojenie"></a> Приложение: Руководство пользователя

Travel RAG помогает составить программу знакомства с городом, подобрать
подходящие места и получить сведения о достопримечательностях. 

### А.1. Регистрация и вход

При первом посещении отображается форма авторизации. Переключитесь
на вкладку **«Регистрация»**, укажите логин и пароль, затем нажмите
**«Зарегистрироваться»**. Если логин уже занят или данные не соответствуют ограничениям,
в форме появится сообщение с причиной ошибки. После успешной регистрации 
открывается основной интерфейс. При следующем входе выберите 
вкладку **«Вход»**, введите те же данные и нажмите **«Войти»**.

*Рисунок 1A - Регистрация и авторизация пользователя в Travel RAG*

### А.2. Главный экран и создание диалога

Слева находится история диалогов. Кнопка **«+ Новый диалог»** создаёт
отдельную беседу, а нажатие на название существующего диалога открывает
сохранённые сообщения. Название формируется из первого отправленного вопроса.
В центральной области показываются вопросы пользователя и ответы ассистента.
Внизу расположены поле **«Город / статья»**, список **«Тип запроса»**,
поле **«Твой вопрос»** и кнопка **«Отправить»**.

*Рисунок 2A - Главный интерфейс туристического ассистента и выбор типа запроса*

### А.3. Планирование туристического маршрута

Выберите **«Планирование маршрутов»**, укажите город и желаемое количество
дней. В вопросе полезно обозначить цель поездки: первое знакомство с городом,
интерес к историческим местам или предпочтение определённого типа объектов.
Ответ отображается в виде карточек по дням. Внутри каждой карточки указаны
названия остановок, краткие описания и номера источников. Для маршрута
обычно подбирается до трёх остановок на день. Если подтверждённых объектов
недостаточно, программа может предложить меньше мест.
Маршрут следует воспринимать как основу программы поездки. Порядок остановок
приблизительно сгруппирован по разделам путеводителя

*Рисунок 3A - Планирование туристического маршрута*

### А.4. Получение рекомендаций

Выберите **«Рекомендации»**, если требуется список подходящих мест
с пояснениями. Укажите город, интересующую категорию и желаемое количество
вариантов. Ограничения лучше формулировать явно: какие места исключить
или какой тематике должен соответствовать подбор.

*Рисунок 4A - Рекомендации на основе найденных источников*

### А.5. Справочные вопросы и проверка источников

Для вопроса о конкретном объекте выберите **«Справочная информация»**.
Укажите город и название места, затем сформулируйте, какое именно сведение
нужно получить. 

*Рисунок 5A - Справочная информация об объекте с указанием источника*

### А.6. Загрузка собственного документа

Документы позволяют задавать вопросы по своему путеводителю или программе
поездки. Поддерживаются PDF, DOCX и TXT. 
Раскройте панель **«Документы диалога»** над полями ввода вопроса.
Нажмите **«Выбрать файл»** и укажите нужный PDF, DOCX или TXT. 
Нажмите **«Загрузить»** и дождитесь завершения обработки. 
Убедитесь, что появилось сообщение **«Загружено: …, чанков: …»**,
а имя файла отображается в списке документов.
Загруженный файл используется в пределах текущего диалога. 


*Рисунок 6A - Загрузка пользовательского документа и семантический поиск по нему*

### А.7. История, учётные записи и завершение работы

Вопросы и ответы сохраняются в истории текущего пользователя.
Другая учётная запись имеет собственный список
диалогов и документов.

Для завершения сеанса нажмите **«Выйти»** в нижней части боковой панели.
Выход не удаляет историю. На общем компьютере завершайте сеанс перед тем,
как передать браузер другому пользователю.
