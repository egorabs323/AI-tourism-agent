# Туристический RAG-ассистент — этап 1: подготовка базы знаний

**Вариант 117**. Основной корпус: [Wikivoyage Geotagged](https://huggingface.co/datasets/yuiseki/wikivoyage-geotagged), конфигурация `20260901.en` (29 505 англоязычных геопривязанных статей). Лицензия: CC BY-SA 4.0. Данные получены из дампа Wikivoyage 1 сентября 2026 года. Требуется интернет при первоначальной загрузке.

## Установка в Windows / PowerShell (Python 3.10+)

Откройте в VS Code папку проекта и выполните в терминале:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## 1. Проверка скрипта без интернета

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe prepare_dataset.py --input-jsonl examples/demo_articles.jsonl --output data/demo
```

Два искусственно созданных тестовых документа лежат в `examples/demo_articles.jsonl`: **это не записи настоящего Wikivoyage**.

## 2. Пробная загрузка 100 статей

```powershell
.\.venv\Scripts\python.exe prepare_dataset.py --limit 100 --output data/preview
```

## 3. Обработка полного корпуса

```powershell
.\.venv\Scripts\python.exe prepare_dataset.py --limit 0 --output data/processed
```

При проблемах с потоковой загрузкой можно повторить с `--no-stream` (скачивает датасет обычным способом, может потребовать больше оперативной памяти):

```powershell
.\.venv\Scripts\python.exe prepare_dataset.py --limit 0 --output data/processed --no-stream
```

Не закрывайте терминал и не выключайте компьютер во время выполнения. Скрипт перезаписывает файлы выбранной папки и не поддерживает возобновление с середины.

## Результаты

В папке `data/processed` создаются:

- `articles.jsonl`: очищенные статьи с оригинальными ссылками, ID и координатами;
- `chunks.jsonl`: чанки для будущей векторизации, идентификаторы, текст, ID статьи и метаданные;
- `stats.json`: фактические показатели качества и объема данных;
- `preview.json`: три примера подготовленных чанков.

Файлы JSONL содержат по одному JSON-объекту в строке, в UTF-8. Открывать целый `chunks.jsonl` в редакторе необязательно — он может быть большим.

### Логика обработки

1. Получение набора `yuiseki/wikivoyage-geotagged` / `20260901.en` из Hugging Face.
2. Проверка обязательных полей `id`, `title`, `url`, `text`; проверка допустимых координат.
3. Нормализация пробелов и HTML-сущностей. Исходный `text` уже превращен автором датасета из вики-разметки в текст — повторный парсер Wiki XML не нужен.
4. Исключение повторяющихся ID и коротких текстов (по умолчанию менее 120 символов).
5. Чанкинг по **220 слов**, с перекрытием **40 слов**. Заголовок статьи включается в содержимое каждого чанка.
6. Сохранение исходного URL и лицензии для корректной атрибуции в ответах.

**Важно:** это первый этап: база ChromaDB и эмбеддинги будут реализованы отдельно. `gt_country`, `gt_region`, `gt_type` и `gt_name` у выбранного корпуса всегда пустые, поэтому скрипт на них не опирается. Координаты относятся к статье в целом, а не к каждой достопримечательности внутри статьи. Построение точных GPS-маршрутов и проверка актуальных часов работы в этот этап не входят.
